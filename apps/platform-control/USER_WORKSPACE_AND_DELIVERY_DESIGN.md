# 用户空间、镜像与部署：需求和初步设计

> 状态：产品需求与初步设计，不代表下述能力已经实现或部署。最终实现需经过权限、恢复、配额和资源回收验收。

## 用户入口与数据归属

用户通过 LibreChat 登录后应能明显看到自己的「我的空间」，查看容量及使用量，上传和下载普通文件、代码，创建目录、编辑文件，并按项目组织资料。用户也可以要求 OpenHands 创建或编辑文件、编译和测试；输出、项目依赖及用户需要保留的编译缓存应保存在其工作空间的持久卷中。文件操作和任务调用必须验证当前身份、空间及项目权限；应防止路径穿越、符号链接跨目录、恶意文件和跨用户访问。上传接口不能允许未经授权的任意路径或覆盖。

工作空间与已验证的 Authentik 身份绑定，而非用户名、邮箱或浏览器传入的用户 ID。暂停、空闲释放计算、沙箱异常和升级不能删除用户持久资料。项目删除、空间删除和账号注销是不同操作；涉及持久数据时应明确影响范围、要求授权和确认、展示保留期与恢复方式，异步执行并记录审计。备份和快照有各自保留期，不应承诺所有副本即时物理擦除。套餐到期或停用默认停止新增消耗并保留资料；具体宽限、只读、保留及最终删除规则需要后续产品政策确定，不能擅自删除。

当前单节点集群不提供节点高可用。数据安全还依赖备份、密钥备份、恢复演练和节点故障处理，不能把独立 PVC 当成备份。

## OpenHands 与构建

共享用户入口和 Agent 编排服务；用户任务在受控的独立沙箱中运行，挂载其独立工作空间。是否每用户复用沙箱、每任务新建沙箱，依据并发、隔离和实测成本选择；不要求每人部署完整 OpenHands 产品。沙箱的进程资源、临时空间、网络及凭据都要限制，用户代码不得获得集群管理员凭据或宿主机 Docker socket。模型调用须关联该用户的 LiteLLM 预算。

不能保证所有工具下载的依赖天然写入用户卷：需要为支持的语言模板显式设置包管理器缓存、构建目录和临时目录，并为容器可写层、日志、构建器缓存单独限制和计量；其他工具仍可能写到工作卷外。应检测和提示磁盘不足，禁止无限制使用节点磁盘。

## Harbor 与用户身份

每位新注册用户应幂等创建一个私有 Harbor project，名称由平台生成的稳定标识派生；不能把未经验证的用户名直接作为权限依据。建立失败需要记录为待重试并对用户可见；对已有用户应提供安全的幂等补建。这个 Harbor project 是镜像仓库命名空间，与开发项目不是同一个概念；用户的多个开发项目可在其专属 Harbor project 下拥有多个镜像仓库。

用户可从 LibreChat 发起构建并将镜像推送到自己的 project。推荐由隔离构建任务使用只授权该 project 的受控机器人凭据，短期持有、轮换及撤销；不得向用户代码提供 Harbor 管理员或其他用户的凭据。若允许用户直接在自己的命令行推送，也只能授予其自己项目所需的最小权限。是否授予用户管理项目成员、删除镜像或修改配额必须单独决定，不能把用户称为业务空间所有者就默认授予全部 Harbor 管理权限。

用户可通过 Authentik 单点登录 Harbor，查看获授权的私有项目和镜像；Harbor 需要先配置 OIDC 并将用户身份与项目成员关联。Harbor 的 OIDC 用户通常在首次 Harbor 登录时完成用户记录创建；注册时创建项目与首次登录时补齐成员授权需设计成可重试流程。Docker/Helm 命令行不能直接使用浏览器跳转登录，Harbor 提供 CLI secret；自动化建议使用范围受限的机器人凭据。[Harbor OIDC 文档](https://goharbor.io/docs/main/administration/configure-authentication/oidc-auth/)、[项目机器人账号](https://goharbor.io/docs/2.5.0/working-with-projects/project-configuration/create-robot-accounts/)

上线前必须只读核查现有 Harbor 认证模式、已有本地账号和管理员恢复方式：Harbor 文档对从本地数据库切换至 OIDC 有前置限制，不能为了接入 SSO 直接切换现有生产实例或删除账号。CLI secret、机器人凭据及管理员凭据不进入 Git、浏览器日志或用户代码，泄露时必须能撤销。构建完成后部署应核验镜像所在 Harbor 项目和不可变 digest，不能信任用户提交的镜像地址或可变 tag。[Harbor OIDC 认证限制](https://goharbor.io/docs/main/administration/configure-authentication/oidc-auth/)、[镜像 tag 不可变规则](https://goharbor.io/docs/main/working-with-projects/working-with-images/create-tag-immutability-rules/)

## 部署和存储额度

平台经授权将应用部署到受用户或租户归属管理的独立 namespace，分配服务、内部或外部域名及证书；用户不直接持有集群管理员权限。部署引用已核验的 Harbor 镜像 digest；集群拉取使用只读、受限凭据。应用运行时 PVC 与开发工作卷默认分离，避免线上应用与 Agent 同时修改源代码或使用 RWO 卷发生冲突；确需共享数据时需单独设计访问模式及权限。

产品可展示一个「总存储额度」，但底层至少包括工作空间 PVC、应用 PVC、Harbor 镜像和可能的对象存储/数据库等独立系统。推荐先明确：额度覆盖的类别、按已分配容量还是实际使用量计算、快照及备份如何计费；第一版可以用**已预留容量**限制工作空间和应用 PVC 总额，并分别为 Harbor project 设置镜像配额，展示各项与总数。真正跨系统的统一硬上限需要控制面做预留、并发事务、拒绝、释放和持续对账，单靠 Kubernetes ResourceQuota 或一块 PVC 无法覆盖；Harbor 项目镜像配额也有其单独的去重计算规则。[Harbor 项目配额](https://goharbor.io/docs/edge/administration/configure-project-quotas/)

Longhorn 的快照、副本和备份会改变物理占用；实际节点剩余空间还会受其他用户、日志和镜像影响。即使逻辑额度足够，也必须在节点容量不足时拒绝创建或排队，不能承诺无限供应。[Longhorn 空间使用说明](https://longhorn.io/kb/space-consumption-guideline/)

## 等级、模拟支付与权限

用户等级/套餐是服务端的权益记录，可以定义总存储、同时运行的应用数量、沙箱 CPU/内存、并发任务和模型额度；后台以实际记录和受控预留校验，不能仅通过隐藏按钮执行。应用数量需明确统计口径：运行中、已停止但保留配置、失败或回收中的应用如何计算。降级后的存量超额处理不能静默删数据，应明确只读/停止新建、宽限期和告知规则。

第一版只做测试订单与受控模拟付款确认，不接真实资金：未获权益时拒绝超套餐操作，模拟付款后生效，重复回调/确认不重复发放，普通用户不得自行伪造付款确认；记录审计。真实支付后续另行实现签名校验、金额校验、订单幂等、对账、退款及失败恢复。

## 主要实现与验收顺序

1. 工作空间生命周期及 LibreChat「我的空间」：创建/上传/编辑/下载、用量、停止与恢复、用户确认删除；双用户隔离和断电恢复。
2. OpenHands 用户任务和文件事件：独立 Kata、持久卷、用户模型额度；验证依赖缓存、文件权限和终止任务后的恢复。
3. Harbor 私有项目自动开通、现有用户补建、OIDC 映射及受限构建机器人；双用户交叉 push/pull、重试、凭据撤销和登录验收。
4. 受限镜像构建与发布到独立 namespace，应用卷、资源数量配额、域名、健康检查、下线和回滚；先实现清理再开放创建。
5. 套餐、统一资源账本、模拟订单和管理员界面；覆盖并发额度、降级、删除失败、恢复和对账。

当前系统已具备登录、LibreChat 对话、自动 LiteLLM 用户密钥、开发项目记录与单独的沙箱技术验收。以上工作空间 UI、自动创建真实用户沙箱、Harbor 用户项目和用户部署均未实现，不能把现有计划接口当作已开通。

2026-11-02 第一阶段进展：控制面源码已增加用户卷的文件操作基础和单卷内部文件服务原型，并在临时 Kata 沙箱、Longhorn 测试卷中验证隔离、文件写入、受限读取、暂停恢复及测试卷回收。服务尚未部署，也没有连接用户身份、空间归属、加密传输或 LibreChat；因此用户还不能在界面上传或编辑工作空间文件。具体契约、限制和验收结果见控制面仓库 `docs/workspace-files-contract.md`。
# 持久卷回收保护（实施中）

用户工作空间计划使用独立的 `codechat-workspace-retain` Longhorn 存储类，回收策略为 `Retain`；普通 `longhorn` 存储类目前为 `Delete`，不能作为用户持久空间的默认策略。删除 PVC 或命名空间后，保留策略旨在留下 PV 和底层卷供受控恢复，而不是自动完成恢复。保留卷不会自动释放容量，也不等同于备份：单节点故障、误删底层卷或磁盘损坏仍可能造成数据丢失。上线前仍需完成备份恢复演练、卷身份绑定和经授权的数据销毁流程；暂停环境不得删除 PVC。
