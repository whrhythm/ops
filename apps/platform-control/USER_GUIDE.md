# 开发空间使用手册

版本：`0.1.0-20261031.1`；更新：2026-10-31。

## 1. 当前能做什么

平台已部署到 k3s，可使用 Authentik 登录，创建个人空间和项目，申请工作空间、编程助手、数据库、对象存储与应用部署，查看容量预留和规划状态，并取消尚未开通的申请。

当前页面是供内部验证使用的资源申请与状态控制台，包含一些偏管理的概念。面向普通用户的聊天、文件编辑、运行测试与发布工作台，以及单独的管理员界面，仍在后续设计范围内。

**当前是资源申请与规划版本。** “方案已生成”表示计划 worker 已处理申请，尚未创建真实开发环境。当前不能在平台中创建源码文件、运行测试、调用编程助手、连接项目数据库或发布可访问的项目站点。现有独立 OpenHands 验证实例也不会自动分配给平台用户。

## 2. 首次访问

平台地址：<https://platform.k3s.local:30443/>。

登录服务：<https://authentik.k3s.local:30443/>。

两个域名都需要正确解析，并信任运维提供的内部 CA。不要把登录地址改为 IP，OIDC 回调和证书校验需要使用上述完整域名及端口。

### 方法 A：客户端能直接访问 Tailscale 地址

在客户端 DNS 或 hosts 中配置：

```text
100.92.98.122 platform.k3s.local authentik.k3s.local
```

位于服务器原局域网的客户端，可将该地址换为 `192.168.10.30`。

### 方法 B：通过 SSH 隧道访问

如果浏览器不能直接访问目标 Tailscale 网络，在可正常 SSH 的终端（例如 WSL）执行并保持运行：

```bash
ssh -N -L 127.0.0.1:30443:192.168.10.30:30443 edge@100.92.98.122
```

将客户端的两个域名解析到本机：

```text
127.0.0.1 platform.k3s.local authentik.k3s.local
```

两种方法选一种；不要为同一域名同时保留冲突的 hosts 条目。Windows hosts 文件是 `C:\Windows\System32\drivers\etc\hosts`，通常需要管理员权限编辑。

隧道方法下，关闭 SSH 终端会中断浏览器连接，但不会停止集群中的平台服务。若本地 30443 已被占用，先关闭冲突程序；直接改成本地其他端口会导致当前 OIDC 回调地址不匹配。

### 信任内部 CA

请从集群管理员获取 `internal-ca.crt`，核对来源后导入浏览器使用的受信任根证书存储。Windows 通常可双击证书，选择安装到当前用户的“受信任的根证书颁发机构”，然后重新打开浏览器。受组织管理的电脑请采用组织规定的证书分发方式。

运维可以导出公开 CA；以下命令不导出私钥：

```bash
kubectl -n platform-system get configmap platform-ca \
  -o jsonpath='{.data.internal-ca\.crt}' > internal-ca.crt
```

如需使用本地配置文件，在命令中增加 `--kubeconfig /mnt/e/Downloads/Blank/.kube/config`。不要关闭浏览器或服务端的证书校验来代替安装 CA。

## 3. 账号与登录

1. 打开平台，点击“使用 Authentik 登录”。
2. 输入 Authentik 用户名和密码，完成组织要求的其他验证。
3. 首次访问会出现授权确认，确认应用为“开发空间”后继续。
4. 回到平台，进入个人空间创建页或已有项目工作台。

Authentik 账号与 SSH 账号是两个系统，不能假定密码相同。本次部署没有修改现有 Authentik 用户密码；文档不保存密码。

当前未配置自助注册流程。新用户需由 Authentik 管理员在管理控制台的用户页面创建、设置初始密码并通过合适渠道交付。无需为普通平台用户创建 Linux 账号或提供 kubeconfig。

访问令牌有效期为 15 分钟，当前界面不自动续期。出现登录过期提示时，刷新页面并重新点击统一登录。当前令牌保存在页面内存中，刷新页面也会回到登录入口；项目和申请记录保存在 PostgreSQL，不会因刷新而丢失。

## 4. 创建个人空间和项目

首次登录后，在“创建你的个人空间”中输入空间名称并提交。每个用户只能创建一个个人空间，也可以由其他空间的 owner 邀请加入。

进入空间后，在“新建项目”中输入名称，例如 `my-project`。项目名称使用小写英文字母、数字和连字符，首尾使用字母或数字；不要包含空格、斜杠或中文。界面使用同样的规则约束资源名称。

通过“当前空间”和“当前项目”切换查看范围。当前权限模型为租户级共享：同一空间的成员可按角色查看该空间全部项目，尚未提供同一租户内部的私有项目权限。

## 5. 申请资源

选择项目后，在“申请新资源”中选择类型、填写名称并提交。

| 类型 | 操作 | 当前结果 |
| --- | --- | --- |
| 工作空间 | 填写资源名 | 预留容量并生成独立工作空间的部署方案 |
| 编程助手 | 选择本项目尚未取消的工作空间 | 生成 OpenHands 绑定方案；一个工作空间最多一个助手分配 |
| 数据库 | 填写资源名 | 生成独立数据库与角色的开通要求；不返回可用连接串 |
| 对象存储 | 填写资源名 | 生成独立 bucket、策略及配额方案；不生成可用访问密钥 |
| 应用部署 | 填写资源名和已审核镜像地址 | 预留容量并生成部署方案；不创建公开项目域名 |

部署镜像必须位于 `harbor.k3s.local/internal/`，并包含不可变 digest，例如：

```text
harbor.k3s.local/internal/my-app@sha256:<64位十六进制摘要>
```

`latest` 等普通标签不能作为发布依据；上述 `<...>` 是格式说明，不能原样提交。

当前界面采用默认规格，更多规格与开发/生产环境字段见 API 契约；界面尚未提供这些字段的完整编辑器。

| 资源 | 默认预留 |
| --- | --- |
| 工作空间 | 500m CPU、1024 MiB 内存、5 GiB 存储 |
| 应用部署 | 250m CPU、512 MiB 内存 |
| 对象存储 | 1 GiB 存储 |
| 编程助手 | 绑定已有工作空间，不另计一套 CPU/内存；仍占一条资源数量额度 |
| 数据库 | 当前只计资源数量；尚无数据库磁盘硬配额承诺 |

## 6. 状态、额度和取消

| 界面状态 | 含义 |
| --- | --- |
| 已提交 / requested | 已保存申请并预留容量，等待计划 worker |
| 方案已生成 / planned | 已生成计划，尚未实际开通；API 中 executable=false |
| 已取消 / cancelled | 未开通的申请已取消并释放预留，记录保留 |

点击“刷新”查看最新状态。计划 worker 通常每两秒检查任务；这不是开通耗时保证。当前没有终端、运行测试、已发布网址或真实数据库访问按钮。

空间默认额度为 3 个项目、4000m CPU、8192 MiB 内存、40 GiB 存储、20 条有效资源记录；管理员可以调整。界面显示的是**预留容量**，不是实际 CPU 使用、磁盘文件大小或费用。申请尚未运行也会占预留，以避免并发超额。

取消申请时点击对应记录的“取消申请”。工作空间已绑定助手时，先取消助手再取消工作空间。已取消记录不会恢复运行；重新申请需提交新申请。

网络异常或冲突提示时，先刷新列表确认提交结果，避免反复点击。API 调用方应保留同一个 Idempotency-Key 重试；取消后复用原 key 仍返回原来的已取消记录。

## 7. 管理员与成员

| 角色 | 能力 |
| --- | --- |
| owner | 管理本空间项目与申请、管理成员、查看审计 |
| admin | 管理本空间项目与申请、查看成员和审计；不能修改 owner 或成员角色 |
| developer | 查看并创建项目与资源申请、取消未开通申请 |
| viewer | 只读项目、资源、任务与额度 |
| 平台管理员 | 通过专用管理 API 列出租户、调整租户总额度；不会自动获得普通项目接口的成员权限 |

现有 `akadmin` 已加入 Authentik 的 `platform-admins` 组。其他平台管理员由 Authentik 管理员审核后加入该组；组自身不授予 Authentik 超级管理员权限。修改身份组后需重新登录，使新令牌携带更新的组声明。

成员管理、额度调整和审计当前提供 API，尚无完整的管理员界面。由具备对应权限的人员按 OpenAPI 操作：

| 接口 | 权限 |
| --- | --- |
| PUT `/v1/tenants/{tenant_id}/members` | owner；按用户的 OIDC subject 分配 admin/developer/viewer，subject 不是用户名 |
| DELETE `/v1/tenants/{tenant_id}/members/{subject}` | owner；不能移除 owner |
| GET `/v1/tenants/{tenant_id}/quota` | 本空间成员 |
| GET `/v1/tenants/{tenant_id}/audit` | owner/admin |
| GET `/v1/admin/tenants` | 平台管理员 |
| PUT `/v1/admin/tenants/{tenant_id}/quota` | 平台管理员；新额度不得低于已预留容量 |

接口文档为平台的 `/docs` 与 `/openapi.json`。业务调用使用当前用户的 access token，不使用 ID token、共享管理员 token 或自报身份的请求头；不要把 token 发到聊天、工单或仓库中。

## 8. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 无法解析域名 | 检查两个域名的 DNS/hosts 条目是否正确、是否存在冲突 |
| 连接超时 | 检查 Tailscale 或 SSH 隧道，确认本地 30443 未被其他程序占用 |
| 证书不受信任 | 安装正确内部 CA，核对域名；不要直接使用 IP 或跳过校验 |
| redirect_uri 不匹配 | 保持完整平台 URL `https://platform.k3s.local:30443/`，检查登录 provider 的严格回调配置 |
| 401 | 令牌缺失或过期，重新登录；运维再检查 issuer/audience/scope/JWKS |
| 403 | 当前角色不具备该操作权限；不是让用户改请求头自报 admin |
| 404 | 记录不存在或不属于当前用户可访问范围，检查空间/项目选择 |
| 409 | 额度不足、同名资源、重复幂等键冲突或仍有关联助手，先刷新记录 |
| 申请一直已提交 | 运维检查 platform-worker 日志和数据库连接；不要手工将记录改为运行中 |
| Argo CD 健康但页面打不开 | 同时检查 ApisixRoute/ApisixTls 的 Accepted 条件；健康不代表路由已下发 |
| 刷新后需要重新登录 | 当前令牌仅保存在页面内存中，是已知行为；数据仍保存在服务端 |
